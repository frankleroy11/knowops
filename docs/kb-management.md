# 知识库改名与永久删除

管理控制台 → 知识库 → 改名 / 删除。仅管理员可操作；租户管理员只管理本租户，跨租户返回 404。编辑者仍可按已有规则更新其他元数据。

## 接口

- `PATCH /api/v1/knowledge-bases/{id}`，JSON `{"name":"新名称"}`。去除首尾空白，空名称 422，重名 409。
- `DELETE /api/v1/knowledge-bases/{id}`，JSON `{"confirm_name":"当前完整名称"}`。确认名称不匹配 409，重复删除 404。
- 删除返回文档、版本、切片数量和 `file_cleanup_pending`。该值非零表示数据库已删除，但仍需通过 `scripts/storage_gc.py` 检查和回收遗留文件。

## 一致性与并发

删除锁定知识库、版本和索引行；写入操作锁定知识库，解析和索引操作锁定版本。存在 pending 解析或 indexing 索引时返回 409。删除后的排队任务读取不到版本，不再生成数据。

先校验存储路径，再清理当前及历史索引集合中该知识库的向量，然后依次删除反馈、成员、索引、切片、版本、文档和知识库。删除审计与业务 SQL 同事务提交，历史审计保留。提交后只回收没有被其他版本引用的文件。前端清理受影响的会话缓存并忽略过期请求结果。

MySQL、Milvus 与文件系统没有分布式事务：向量失败时返回 503，保留 SQL 和文件，但部分集合可能已清理；SQL 提交失败也返回 503，向量可能已清理。需要重试删除；此时检索可能暂时缺失。文件清理失败通过 `file_cleanup_pending` 报告。没有实现软删除、自动补偿任务或恢复功能。

Milvus 客户端使用独立连接别名，避免清理客户端关闭后使同进程其他检索客户端失效。
