# 可选同文档上下文补全

分支fix/citation-completeness，接续草稿PR #1。默认关闭，前端可勾选“补充同文档资料”，
API使用expand_context=true。单库和全部知识库模式都支持，原top_k继续控制向量检索的原始命中数。

## 机制和边界

先保留所有原始命中，再读取同一文档版本中position前后各一片，优先补前片再补后片；
按chunk_id去重，总量最多8片，每片送模型的正文最多1200字符。
SQL再次检查文档解析状态和当前向量集合的版本索引状态，结果核对version_id/document_id/knowledge_base_id。
补充片段只来自命中文档，不能借此进入未命中的知识库、另一版本或距离更远的片段。
邻接片段没有向量相似度，不伪造score；context_role区分原始命中和neighbor。
引用仍指向实际片段，返回原知识库名称。提示词增加文件名及知识库信息，并要求区分具体表格与通用条款。
filename也是不可信数据，不执行其指令。

API响应新增context_chunk_count与context_expanded；后者表示开关是否启用，不保证实际多取到了片段。
没有相邻内容、原命中已经达到8片或候选完全重复时，实际片数可能不增加。
这项功能不改变Milvus集合、索引、向量排序默认值或旧评测标签。

## 使用与复现

```json
{"question":"80万元合同的审批人和时限？","scope":"all","top_k":3,"expand_context":true}
```

运行python scripts/evaluate_context.py生成新存档，最多36次Qwen调用；需要已有synthetic-v1知识库、API、MySQL和Milvus。

保留默认关闭及PR草稿状态。已验证具体切片缺失案例，但仍有模型误拒答、语义支持验证和更远证据覆盖问题；
在新的独立题集和人工复核前，不自动切换生产默认方案。
