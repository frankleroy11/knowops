# 系统状态页

入口：管理控制台 → 系统状态。仅平台管理员可见；租户管理员/普通成员请求 `GET /api/v1/admin/system/status` 返回 403，强制认证下未登录返回 401。`AUTH_MODE=off` 延续本地平台管理员模式。

手动刷新同时执行 MySQL SELECT 1、Redis PING、Milvus 集合列表查询、Celery registered 控制探测和 MySQL 文档/索引状态聚合。展示检查时间、各项状态与检查耗时。基础服务各自设置连接/读写超时；Worker 等待响应 2 秒，各检查并行执行。没有自动轮询或测试任务，不写业务数据，不返回地址、密钥或底层异常。MySQL 连接池等待等额外开销可能使总耗时超过单项超时。

只统计同时注册 KnowOps 解析和索引任务的 Worker，忽略其他应用的 Worker。solo Worker 执行长任务时可能无法响应控制消息，所以无响应显示“待确认”，不能断言离线。响应也只证明控制通道和任务注册，不证明模型、队列消费和答案质量。

文档状态是全局数据库业务快照，不是消息队列长度。基础服务正常时仍可能存在失败文档，应独立处理。单项异常返回脱敏的 unavailable，其他项继续展示；HTTP 200 携带 degraded，区别于认证或接口请求失败。刷新开始清除旧结果，避免失败后将旧状态误认为最新。
