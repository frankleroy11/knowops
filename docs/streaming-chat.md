# SSE 流式问答

`POST /api/v1/chat/stream` 接受与 `/chat/ask` 相同的参数和身份认证。旧同步接口保留。前端默认使用新接口。

事件顺序为 `status`、零或多个 `progress`、零或多个 `delta`、`done`。失败返回 `error`，不发送 `done`。认证及参数校验仍可直接返回 HTTP 错误；流开始后的业务错误通过 SSE 事件发送。`done` 保留完整答案、引用、来源类型和耗时。

RAG 调用 Qwen 的 `stream=true`，通过 LangChain 原提示词和完整 JSON 解析链处理。`progress.characters` 是已收到的模型 JSON 字符数，不是 token 数，也不是已经验证的答案长度。收到完整模型响应和 `[DONE]` 后，仍执行原有完整性和逐事实引用校验。通过后按至多 24 字符发送正文片段，无人为打字延迟。FAQ、缓存、拒答也使用相同事件协议。

这是“生成进度实时更新 + 校验后正文分段传输”，不是模型首 token 直接显示；正文首字延迟仍包含完整生成和验证时间。这样避免把最终应当拒答的中间 JSON 或未经校验的事实提前展示给用户。后续如需真正边生成边显示正文，需要明确支持暂定内容和撤回协议。

后台线程使用独立数据库会话。队列有界，客户端断开后停止事件输出；已经执行中的检索或等待模型网络数据不能瞬间取消，受现有 HTTP 超时限制。前端请求总超时 180 秒，截断流视为失败，移除部分答案并恢复问题；流式中间态不写入会话持久化。引用和反馈仅在完成后可用。

验证包含：完整事件与错误事件、模型流结束标记缺失、中文 UTF-8/CRLF 跨字节分块、前端截断和错误流。生产代理需关闭 SSE 缓冲（响应已设置 `X-Accel-Buffering: no`）。没有新增在线付费模型验收。
