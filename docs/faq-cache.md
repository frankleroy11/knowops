# FAQ 优先匹配与 Redis 问答缓存

## 当前流程

```text
问题 → 身份及知识库权限 → 当前有效版本快照
     → FAQ 精确匹配 / 语义匹配
         命中：返回管理员维护的答案和原文证据，不调用 Qwen
         未命中：Redis 精确请求缓存
             命中：复核当前正文及引用后返回
             未命中：原有 RAG → 引用校验 → 成功结果写缓存
```

原有 RAG 仍为 BGE-M3 → Milvus 召回 → SQL 正文和状态复核 → 可选重排／邻块扩展 → LangChain + Qwen → 逐事实引用校验。

## 存储分工

- **MySQL `faqs`**：标准问题、人工维护答案、证据块、逐字摘录、启用状态和问题向量。问题向量由 BGE-M3 生成，携带编码配置身份。
- **Milvus**：原有知识库文本块的向量索引。本轮没有再建立独立 FAQ 集合。
- **Redis**：使用 `knowops:answer:v1:` 前缀缓存已通过引用校验的成功 RAG 回答，默认 TTL 300 秒，与 Celery 队列共用服务但键空间分离。

FAQ 初版面向小规模人工维护：每库最多 200 条，在 SQL 候选中计算余弦相似度；授权范围超过 1000 个有效语义候选时跳过语义扫描，仍可精确匹配并回退 RAG。更大规模应迁移到独立 FAQ 向量索引，而不是宣称 MySQL 原生实现了向量近邻搜索。

## 管理使用

管理员登录 → 管理控制台 → **高频问答** → 选择知识库 → 填写问题和标准答案 → 选择有效证据块 → 摘录连续原文 → 保存。

答案需要管理员人工核对，系统只验证摘录存在且来源有效，不自动证明答案语义正确。FAQ 暂不从访问日志自动提炼，也不把模型回答自动升级为标准答案。

本机通过页面保存了一条演示 FAQ，位于 `入库验证-fea30618`：

> 操作流程.txt 中第一步和第二步分别是什么？

答案“第一步登录，第二步查询。”由原有 `操作流程.txt` 的完整正文直接支持。可在统一问答中使用这个完整问题测试。

## 命中规则

1. 问题精确匹配只折叠空白和大小写，不删除数字、否定词、单位或标点。
2. 精确未命中时，问题编码后与 FAQ 问题向量比较，默认阈值 0.85。
3. 两个语义候选得分差小于 0.05 时回退 RAG；完全相同问题却有不同标准答案时也回退。
4. 向量维度或编码配置不兼容时跳过相应语义候选；精确匹配仍能使用人工维护答案。
5. 阈值和领先差距属于开发配置，需要真实正反样本校准，不是“85% 正确率”。FAQ 的语义误匹配仍可能发生，本轮未完成代表性大样本阈值评测。

## 权限与失效

所有 FAQ 都绑定知识库和一个具体文本块。只读用户可命中自己有权读取的 FAQ，不能维护；管理员只能维护授权范围内的条目。来源必须属于当前、已审核、已解析、已索引且未下架的版本。

下架、版本切换或索引失败使对应 FAQ 不再命中。删除文本块或知识库会通过数据库外键级联删除绑定 FAQ；不要依赖重新发布已删除资料恢复它。

缓存每次读取前查询当前授权和版本状态。键包含用户身份、租户、角色、知识库范围、当前版本、块计数与最大 ID、FAQ 内容及启用状态、模型／提示词／重排配置和完整提问参数。读取时还从 SQL 核对引用块正文及归属，并复核 claims 与摘录。权限变更、版本或 FAQ 变更导致旧键不可达；旧键由 TTL 回收，不执行全库清空。

缓存为精确请求缓存，不做“相似问题共用答案”。拒答、异常和引用校验失败不会写入缓存。Redis 超时、故障或内容不合法时回退 RAG。模型故障也不会被隐藏为成功回答。

状态快照沿用请求级 SQL 事务语义，不提供跨 SQL／Redis／Milvus 的线性一致性；并发修改与已经进行中的请求仍需按开发版边界理解。绕过应用直接改表不是受支持的失效接口。

## 配置和接口

```env
FAQ_ENABLED=true
FAQ_SIMILARITY_THRESHOLD=0.85
FAQ_SIMILARITY_MARGIN=0.05
ANSWER_CACHE_ENABLED=true
ANSWER_CACHE_TTL_SECONDS=300
```

迁移：`python -m alembic upgrade head`，本轮新增 `0013`。其他机器部署须先迁移，再启动 API。环境变量更改后重启 API。

| 接口（统一前缀 `/api/v1`） | 用途 |
| --- | --- |
| GET `/admin/faqs?knowledge_base_id=...&offset=0` | 管理列表，每页 50 条 |
| GET `/admin/faqs/sources?knowledge_base_id=...&offset=0` | 有效原文块，每页 100 条 |
| POST `/admin/faqs` | 新增 |
| PUT `/admin/faqs/{id}` | 全量编辑或停用 |
| DELETE `/admin/faqs/{id}` | 删除 |
| POST `/chat/ask` | 自动走 FAQ / 缓存 / RAG，返回 `answer_source` 与 `cache_hit` |

## 验证

新增 25 项离线测试涵盖精确命中跳过模型、0.85 阈值两侧、相近候选回退、不同答案冲突、过期来源、跨租户、只读拒绝管理、缓存用户与参数隔离、TTL 配置、权限撤销、版本／FAQ 编辑、Redis 故障和非法缓存、拒答不缓存及错误向量。

`scripts/check_faq_cache.py` 使用真实 MySQL、Redis、Milvus、Worker、BGE-M3 与 Qwen，合成临时文档完成 4 组验收，临时业务对象已按 ID 清理。测试缓存采用短 TTL 自然失效，不触碰其他用户键或任务队列。原始结果见 [验收记录](../evals/faq_cache/acceptance-20261016.json)。

本次浏览器实际创建并看到了演示 FAQ；新增界面和既有前端测试／构建通过。本轮只证明开发链路可运行，不证明 FAQ 语义误匹配率或问答准确率提升。

本轮最终检查为 301 项后端、18 项前端测试通过。一次合成请求样例的服务端总耗时：FAQ 精确约 9.87 ms，语义约 29.01 ms，RAG 约 3384.64 ms，Redis 命中约 13.39 ms；只是单次开发观察，不是性能压测结论。真实知识库删除也验证了绑定 FAQ 的外键级联清理。
