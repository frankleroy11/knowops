# 失败任务与文档版本管理

管理控制台 → 失败任务：按租户权限列出解析失败和当前嵌入集合的索引失败，50 条分页，显示知识库、文档、版本、失败阶段及脱敏错误。可以打开对应资料页或重试该版本的失败阶段。旧版本的失败也可定位。

`GET /api/v1/admin/document-failures?limit=50&offset=0` 仅管理员使用。编辑者可以在有写权限的知识库资料页重试；只读用户不可重试。解析重试仅允许 failed，先写 pending 再投递，入队失败恢复 failed；等待任务禁止重复投递。上传入队失败现在标记 failed，避免留下不可重试的 pending。索引重试在数据库先标记 indexing；已完成或进行中的索引返回 409，入队失败恢复 failed。Broker 接收与 SQL 之间没有 outbox 事务，极端进程崩溃仍可能需要人工排查。

原有两个失败记录是早期验收夹具：文档 5 `invalid.txt` 含两字节无效 UTF-8，文档 6 `扫描件示例.pdf` 无可提取文字。已对原文件只读解析复验，均为 ParseError。本次保留原始失败案例，未用重试伪装成修复。正确处理是修正文件后上传新版本，扫描件需先 OCR。

## 文档与版本

- `GET /documents/{id}/versions`：有读权限即可查看版本处理、索引、审核及有效状态。
- `POST /document-versions/{id}/publish`：有写权限，且版本已解析、已索引、审核通过才能切换有效版本；知识库锁串行化切换，审计和切换同事务提交。不会绕过审核。
- `DELETE /documents/{id}`：管理员权限，JSON `{"confirm_filename":"当前完整文件名"}`。错名、忙碌任务 409，跨租户 404。

删除锁定知识库、文档、版本及索引，拒绝正在解析/索引的任务；先校验所有存储路径，再清理当前和历史索引集合中该文档的全部向量，删除索引/切片/版本/文档，提交审计，最后回收未被共享的文件。保留知识库、其他文档、审计与历史答案反馈（反馈为答题当时快照，可能仍含已删除文档内容）。不提供软删除恢复；敏感数据全量擦除另需处理历史反馈、日志和备份。

向量或 SQL 失败返回 503，可能已清理部分向量，需要重试。文件失败返回 `file_cleanup_pending` 非零，需通过存储 GC 回收。原文件不使用用户文件名作磁盘路径，拒绝路径穿越。

检索现在在 Milvus 候选召回之前过滤 MySQL 中有权限、审核通过、当前、未下架、已索引的版本，再在 SQL 回表时复验；防止旧版本向量占据 top-k。大量版本下的 IN 过滤表达式规模仍需性能评测。
