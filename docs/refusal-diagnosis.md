## 1. 结论摘要

1. **不是检索或裁剪问题**：两条冻结证据原文都逐字出现在实际送模型的上下文里。
2. **拒答在模型侧，且稳定可复现**：原题在不同策略、不同轮次共 6 次调用全部拒答，`claims=[]`。
3. **触发条件很窄**：单句内用“并”把**两个**“资料只给出固定值或明确禁止”的具体做法连成一个是非问，
   且两项都需要否定推断时，模型把两个子问题都判为“资料未提及”。
4. **能力本身没有缺失**：把同一问题拆成两句、改成确认句式、或换成肯定型复合问句，模型都能正确回答，
   并给出可通过后端逐字校验的摘录（第 4 节已用确定性复算验证）。
5. **两次通用提示词修复尝试都无效**（模型输出逐字相同），已 `git checkout` 回退，当前 HEAD 无 `app/` 改动。
   因此不能靠继续堆提示词解决，需要结构方案（第 8 节）。

在**同一批冻结 sources**（anchors_3，3 片）上只改问句，每题一次生成、不重试替换：

| # | 问句 | 结果 | 要点 |

| 0 | 云盘回调地址能填公网IP并用8443端口吗？（原题） | **false** | 拆成两个子问题，均判“未提及”；3 次重放均如此 |

其中 #1–#6 六次回答的全部 evidence 摘录，已用本地确定性复算按 router 的规则（空白归一后的
逐字包含、source_id 在范围内、唯一匹配）校验：**全部通过，无需任何编号纠正**。
即这些不是“模型自称有依据”，而是可直接通过现有严格校验的答案。

由此可分离三个变量：

- 单一否定推断：正常（#2、#3）。
- 复合是非问句：本身不是触发点（#4 肯定型复合正常）。
- 需要**两处否定推断**的复合问句：只有当两项被“并”连进同一个单句是非问时才触发拒答（#0）；
  拆成两句（#5）或改成确认式（#6）都能正确作答。

## 7. 建议的下一步（尚未实施，需授权）

不建议继续试提示词措辞。按影响从低到高：

1. **诊断字段（低风险）**：拒答响应中保留有界的 `unanswered_questions`（仅模型自述，不含供应商原始报文与密钥），
   让后续回归能区分“模型拒答”与“证据编号问题”。需补测试并确认 API 契约兼容。
2. **结构方案（推荐方向）**：要求模型对每个子问题给出显式裁决（可以 / 不可以 / 资料未提及）后再组装答案。
   本轮已证明模型具备所需事实与否定推断能力，缺的是“必须逐项给出裁决”的结构约束，
   而两次提示词层面的同类约束都无效。
3. **拆句预处理（备选，最激进）**：对含“并/和/同时”的是非问做确定性拆分后分别调用。
   会改变调用次数、时延与聚合逻辑，须先评估成本与引用合并规则，不建议优先做。

任何一条的验收都要求：`ruff check .`、`python -m pytest -q`（当前 76 项）、前端生产构建，
以及 18 题×2 策略成对回归全部存档、不挑选成功重试；并明确区分开发回归收益与新题泛化。
