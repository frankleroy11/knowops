# 统一问答窗口

旧界面必须先选库，/chat/ask 与 /search 都要求 knowledge_base_id。检索按该编号过滤，
因此资料只在另一个库时，选错库会拿不到答案；通常返回资料不足，不一定是接口错误。

现在默认打开“统一问答”，使用显式 scope=all，在当前本机空间全部已存在知识库中进行向量检索。
引用增加 knowledge_base_id / knowledge_base_name，页面可核对资料来自哪个库。
左侧选择具体知识库时仍限制该库，并显示该库文档管理；统一入口不提供无目标库的上传按钮。

请求示例：

```json
{"question":"会议摄像头与桌面线缆分别多久巡检一次？","scope":"all","top_k":3}
```

原请求不变：

```json
{"question":"如何连接VPN？","knowledge_base_id":1,"top_k":3}
```

scope 默认 knowledge_base；漏传 knowledge_base_id 仍422。
all 与 knowledge_base_id 同时出现会422，避免含糊地忽略用户选定范围。
Milvus仍使用MySQL现存知识库编号列表过滤，取回后再次核对文档、解析与索引状态，丢弃失效记录。
单库隔离测试保留，不把全局检索用于原隔离题评测。

这是检索范围的扩展，不保证每个问题都能回答：资料缺失、相似资料太多、不同库口径冲突、
前几条候选未覆盖所有子问题或模型生成问题，仍可能拒答或答错。
目前项目没有用户/权限体系，“全部”表示当前本机空间全部知识库。
未来增加多用户权限后，须将此列表改为当前用户可访问的库，不能直接用于多租户生产环境。

本功能从main独立开发，不包含尚有回归的逐事实引用草稿PR。

## 本轮验证

57项pytest通过、Ruff通过、Vue生产构建成功。真实浏览器在scope=all下分别提问IT巡检与人事婚假问题，
均返回答案并标明对应知识库；范围下拉切换到单库时显示该库标题与文档管理，切回全部时恢复统一问答。
新增测试覆盖两库联合检索、单库过滤不变、数据库失效命中剔除、含糊/非法scope拒绝、
空库列表不触发无过滤向量检索，以及问答接口scope向检索传递。
