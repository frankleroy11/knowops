# 后端代码中文阅读指南

本次为后端、启动入口、数据库迁移和运维／评测脚本补充中文职责与边界说明，并为主要业务入口增加流程注释。未逐行翻译代码或为所有辅助函数添加注释；保留现有英文术语与说明。修改仅涉及注释和文档，不改变运行逻辑。

## 建议阅读顺序

| 位置 | 重点 |
| --- | --- |
| `run.py`、`app/main.py` | API 启动、路由注册与前端挂载 |
| `app/core/config.py`、`app/db/` | 配置、连接池、请求会话与事务边界 |
| `app/modules/auth/`、`tenant/` | 登录、公开注册、平台／租户管理员与知识库授权 |
| `app/modules/knowledge/` | 上传、版本、审核、发布和删除 |
| `app/modules/ingestion/` | 文本／PDF 解析、固定窗口和结构切分 |
| `app/workers/`、`app/modules/retrieval/` | 异步任务、编码、索引、召回和相邻块扩展 |
| `app/adapters/` | 存储、Milvus、嵌入、重排及 Qwen 的技术实现 |
| `app/modules/chat/` | 生成、逐条证据验证与拒答 |
| `app/modules/feedback/`、`audit/`、`system/` | 反馈复盘、审计及运行状态 |
| `app/modules/oidc/` | 可选单点登录与身份令牌验证 |
| `migrations/`、`scripts/` | 数据库版本和实际验收／运维入口 |

账号细节见 [账号代码阅读指南](account-code-reading-guide.md)。

## 上传到问答的流程

1. 接口验证权限，保存上传文件和文档版本，投递 Celery 解析任务。
2. Worker 提取原文，读取版本保存的切分策略，生成文本块。`parsed` 仅表示解析完成。
3. 索引任务将文本块编码，按块 ID 写入 Milvus，成功后更新 SQL 索引状态。
4. 审核／发布流程决定当前可用版本。检索还会要求该版本已批准、已索引且未下架。
5. 问答先确定用户可见的知识库与版本，再召回、可选重排和扩展邻块。
6. Qwen 根据证据生成结构化回答，后端核验引用来源与摘录；校验失败时拒答。

## 最容易误解的约束

- MySQL 是正文和业务状态的权威，Milvus 是可重建的检索索引。向量存在不代表该内容有权参与问答。
- 结构切分按字符长度处理，尽量保留标题、段落、短表格与代码块，输出仍是原文子串；它不是 token 切分或 OCR。
- `audit.service.record` 会提交当前会话事务，业务层须先完成关键校验。
- 删除涉及数据库、向量库和磁盘，不能保证跨存储原子提交；需要关注失败后的残留状态。
- 任务可能重复投递。修改 Worker 代码后必须重启 Worker，API 的热重载不能替代它。
- 引用摘录能在原文中找到，只证明文本匹配，不证明答案在语义上正确。

## 脚本运行前先读文件头

`check_ingestion.py`、`check_retrieval.py`、`check_dataset_pipeline.py` 等会产生真实数据；不要随意导入带顶层执行代码的脚本。`check_release_flow.py` 与 `check_user_accounts.py` 使用临时对象验收，也需要核对清理结果。

备份要求先停止写入者，且当前本地备份不包含 Milvus。审计清理和文件垃圾回收默认预览，显式删除前核对范围。迁移降级可能丢失字段或表中数据。

评测脚本用于开发回归和对照实验。用户反馈需要人工审查后才能成为标准答案；已经用于开发选择的冻结数据不能继续称作独立盲测。

## 本次验证方式

对所有修改的 Python 文件比较修改前后的抽象语法树（AST），确认可执行语句与字符串常量保持一致，并执行 Ruff 和 Git 空白检查。注释修改不需要调用收费模型或重新写入业务数据。
