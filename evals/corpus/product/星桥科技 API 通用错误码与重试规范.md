# 星桥科技 API 通用错误码与重试规范

- 文档编号：XQ-CORP-API-304
- 文档版本：v2.9
- 发布日期：2026-08-17
- 适用产品版本：星桥云盘 3.4.x、星桥工单 4.2.x、星桥会议 2.8.x
- 维护部门：星桥科技开放平台组

## 1. 适用范围

本文规定星桥科技全部开放接口的通用约定：统一响应结构、通用错误码、重试策略、幂等要求与网关限流。各产品特有的错误码请查阅对应产品的错误码文档。本文只描述跨产品的通用层。

## 2. 统一响应结构

所有接口的成功与失败响应都遵循同一结构：

```json
{"code":"OK","message":"success","data":{},"request_id":"req_7c1a2b"}
```

失败时 `code` 为错误标识，`data` 为空。请始终以 `code` 做分支判断，`message` 仅用于展示，会随版本调整文案。`request_id` 在每次请求中唯一，提交工单时必须提供。

## 3. 通用错误码

| HTTP | code | 含义 | 是否可重试 |
| --- | --- | --- | --- |
| 400 | `INVALID_ARGUMENT` | 参数不合法 | 否 |
| 401 | `UNAUTHENTICATED` | 未认证或令牌无效 | 刷新后重试 1 次 |
| 403 | `PERMISSION_DENIED` | 无权限 | 否 |
| 404 | `NOT_FOUND` | 资源不存在 | 否 |
| 409 | `CONFLICT` | 状态冲突或幂等键冲突 | 否 |
| 422 | `UNPROCESSABLE` | 业务校验失败 | 否 |
| 429 | `GATEWAY_RATE_LIMITED` | 网关总量限流 | 是 |
| 500 | `INTERNAL_ERROR` | 服务内部错误 | 是 |
| 502 | `BAD_GATEWAY` | 上游异常 | 是 |
| 503 | `SERVICE_UNAVAILABLE` | 服务不可用或维护中 | 是 |
| 504 | `GATEWAY_TIMEOUT` | 网关超时 | 是 |

## 4. 网关限流

所有请求经过星桥统一网关。网关按租户维度限流，阈值为每分钟 6000 次，超出返回 429 `GATEWAY_RATE_LIMITED`。与其他 429 不同，网关 429 不返回 `Retry-After`，只返回 `X-XQ-Rate-Limit-Reset`，值为限流重置时刻的 Unix 时间戳。

网关限流通常是租户下多个应用叠加造成的，排查时需统计该租户所有应用的调用量。若确需更高阈值，可提交扩容申请，需提供近 7 天的调用量曲线。

## 5. 产品级限流与网关限流的区别

| 限流层 | 阈值 | 响应头 | 处理方式 |
| --- | --- | --- | --- |
| 网关 | 每租户每分钟 6000 次 | `X-XQ-Rate-Limit-Reset` | 全局降速或申请扩容 |
| 星桥云盘 | 每令牌每分钟 600 次 | 无 | 退避重试 |
| 星桥工单 | 每令牌每分钟 120 次 | `Retry-After` | 按 `Retry-After` 等待 |
| 星桥会议 | 每令牌每分钟 300 次 | 无 | 退避重试 |

四条限流互不替代。一次请求可能同时受网关限流与产品限流约束，命中任一条都会返回 429，靠 `code` 区分。

## 6. 重试规范

| 参数 | 建议值 |
| --- | --- |
| 连接超时 | 5 秒 |
| 读超时 | 云盘 30 秒、工单 10 秒、会议 8 秒 |
| 最大重试次数 | 3 次 |
| 退避序列 | 1 秒、2 秒、4 秒（可带随机抖动） |
| 总重试时长上限 | 60 秒 |

只对 429 与 5xx 重试，且必须使用指数退避。禁止对 400、403、404、409、422 重试，这些属于确定性错误，重试不会成功并可能放大问题。总重试时长超过 60 秒仍失败时，应停止并提交工单。

## 7. 幂等要求

创建类的写操作都应携带 `X-XQ-Idempotency-Key`。幂等键在 24 小时内唯一，相同键的重复请求返回首次结果；相同键但请求体不同则返回 409 `CONFLICT`。

幂等键设计建议：使用"业务类型 + 业务主键 + 日期"的组合，长度不超过 64 个字符。不要使用固定字符串，否则第二天的真实请求会被判定为重复。

## 8. 版本与废弃策略

接口路径中的版本号为大版本，大版本不保证兼容；小版本保持向后兼容。标注为废弃的接口至少保留两个小版本，并在响应头返回 `X-XQ-Deprecated: true`。收到该头说明当前调用需要迁移，请查阅产品迁移文档。

已废弃但仍可调用的接口清单：云盘的 `POST /api/v2/files/upload`（自 v3.0 起废弃）、云盘 `sync-legacy` 同步协议（自 v3.2 起废弃）、工单的 `POST /api/v1/tickets/legacy`（自 v4.0 起废弃）、工单鉴权头 `X-Legacy-Token`（自 v4.1 起废弃）、会议的 `room.create`（自 v2.5 起废弃）。

## 9. 接入检查清单

- [ ] 统一解析 `code` 字段，不解析 `message`。
- [ ] 记录并上报 `request_id`。
- [ ] 按产品实现各自的令牌刷新逻辑。
- [ ] 写操作携带幂等键。
- [ ] 按退避序列重试，且只重试 429 与 5xx。
- [ ] 监控 `X-XQ-Deprecated` 响应头。
- [ ] 为 429 与 5xx 分别设置告警。

## 10. 常见问题

**问：网关 429 和云盘 429 怎么区分？**
看 `code` 字段。`GATEWAY_RATE_LIMITED` 是网关层，`UPLOAD_CONCURRENCY_EXCEEDED` 是云盘层。

**问：重试三次都失败怎么办？**
停止重试，收集 `request_id`、时间与请求体后提交工单。

**问：幂等键能复用到不同接口吗？**
不建议。幂等键在同一应用内全局唯一，跨接口复用容易触发 409。
