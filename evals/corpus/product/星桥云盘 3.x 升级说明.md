# 星桥云盘 3.x 升级说明

- 文档编号：XQ-DRIVE-UPG-3X-012
- 文档版本：v1.6
- 发布日期：2026-07-28
- 适用产品版本：星桥云盘 2.9.x 升级至 3.4.x
- 维护部门：星桥科技交付与运维部

## 1. 适用对象

本文面向从 2.9.x 升级到 3.x 的私有化部署客户。它与《星桥云盘 2.x 升级说明》标题相近但要求完全不同：3.x 升级不可回滚、停机窗口更长、对数据库与内存的要求更高，请勿使用 2.x 的窗口安排运维计划。

## 2. 升级前置条件

| 前置项 | 3.x 升级要求 |
| --- | --- |
| 起始版本 | 必须先升级到 2.9.7 |
| 服务端内存 | 至少 16 GB |
| 数据库 | XQDB 15 及以上 |
| 磁盘剩余空间 | 不低于数据总量的 2 倍 |
| 停机窗口 | 90 分钟 |
| 客户端版本 | 3.0 及以上（32 位客户端不再支持） |
| 回滚支持 | 不支持 |

数据库低于 XQDB 15 的客户必须先完成数据库升级，数据库升级需单独申请维护窗口，通常再增加 60 分钟。仍旧运行 32 位操作系统的终端无法升级到 3.x 客户端，需要更换设备。

## 3. 升级步骤

1. 提前 3 天在控制台提交升级申请，系统会自动检查前置条件并生成检查报告。
2. 升级前执行全量快照并导出配置。注意：快照只用于灾备，不能用于回滚到 2.x。
3. 开启维护模式，确认同步队列已排空（队列长度应为 0）。
4. 执行数据库迁移脚本 `xqdrive-migrate-3x`，该步骤通常耗时 40 到 70 分钟。
5. 安装 3.x 服务端安装包，安装完成后执行 `drive-cli doctor`。
6. 确认 `doctor` 输出的 12 项检查全部通过后，关闭维护模式。
7. 分发 3.x 客户端，2.x 客户端在升级后 14 天内仍可只读访问，之后会被拒绝登录。

## 4. 升级后的重大变化

- 单文件上限、回收站保留期等配额随套餐重新计算，基础版单文件上限从 10 GB 降到 5 GB。
- 旧上传接口 `POST /api/v2/files/upload` 自 v3.0 起废弃，请改用 `POST /api/v3/drive/objects`。
- 旧同步协议 `sync-legacy` 自 v3.2 起废弃，请改用 `sync-v3`。
- 访问令牌有效期从 12 小时缩短为 2 小时，接入方必须实现自动刷新。
- 错误码体系重构，`LEGACY_UPLOAD_REJECTED` 取代了原来的 `UPLOAD_FAILED`。

## 5. 兼容性矩阵

| 组件 | 2.9.x 可用 | 3.0 到 3.2 | 3.3 及以上 |
| --- | --- | --- | --- |
| 桌面客户端 2.4 到 2.9 | 是 | 只读 | 拒绝登录 |
| 桌面客户端 3.0+ | 否 | 是 | 是 |
| 旧上传接口 v2 | 是 | 可用但告警 | 已废弃 |
| `sync-legacy` 协议 | 是 | 已废弃 | 已废弃 |
| 移动端 1.x | 是 | 只读 | 拒绝登录 |

## 6. 升级失败的处理

若 `xqdrive-migrate-3x` 中途失败，服务会停留在维护模式并输出失败表名。此时不要手工改表，请收集迁移日志并通过 P0 工单提交。迁移失败后重试是安全的，脚本会从最后一个成功的检查点继续。

## 7. 常见问题

**问：升级要停服务多久？**
标准窗口 90 分钟，含数据库升级的客户预留 150 分钟。

**问：能回滚吗？**
不能。3.x 不提供回滚，只能通过灾备快照做整机恢复，恢复后数据将回到升级前时点。

**问：自定义水印配置会保留吗？**
会保留，但字段结构有变化，升级后需在控制台复核一次。

## 8. 与 2.x 升级的关键差异

两份升级说明标题相近，但结论差异很大，运维排期时务必对照本表：

| 对比项 | 2.x 升级 | 3.x 升级 |
| --- | --- | --- |
| 起始版本要求 | 2.8.5 | 2.9.7 |
| 内存要求 | 8 GB | 16 GB |
| 数据库要求 | XQDB 12 | XQDB 15 |
| 磁盘余量 | 1.5 倍 | 2 倍 |
| 停机窗口 | 30 分钟 | 90 分钟 |
| 是否可回滚 | 支持，24 小时内 | 不支持 |
| 32 位客户端 | 支持 | 不支持 |
| 旧上传接口 | 可用 | 已废弃 |

如果客户同时需要两个维护窗口，建议间隔至少 7 天，避免一次变更引入过多变量导致定位困难。

## 9. 升级窗口与人力安排

标准 3.x 升级建议投入 3 人：1 名数据库工程师负责迁移脚本与慢查询观测，1 名应用工程师负责安装与健康检查，1 名客户成功经理负责用户通知与答疑。窗口安排建议为工作日 22:00 至次日 01:00，预留 150 分钟。

含数据库升级的客户请把窗口提前到 21:00，并在数据库升级前单独做一次快照。数据库升级本身对业务不可见，但会占用磁盘 IO，建议与其他备份任务错开。

## 10. 升级后回归验证清单

升级完成后请按顺序验证：

1. 用管理员账号登录 Web 控制台，确认用量页正常加载。
2. 上传一个 300 MB 文件，确认走分片且并行度达到 8。
3. 删除该文件，确认回收站保留期显示 30 天。
4. 生成一条外链，确认有效期为套餐允许的最大值。
5. 调用 `GET /api/v3/drive/quota`，确认返回 `used_bytes`、`total_bytes`、`recycle_bytes`。
6. 触发一次 Webhook，确认签名头存在且校验通过。
7. 使用旧客户端登录，确认提示升级而未被直接拒绝（升级后 14 天内）。

七项全部通过后，方可通知用户升级完成。

## 11. 降级与灾备

3.x 不提供降级路径。若升级后出现严重问题，唯一的恢复方式是使用升级前的灾备快照做整机恢复，恢复后数据回到升级前时点，期间产生的新数据会丢失。因此升级前务必确认业务处于低写入时段，并在维护模式下排空同步队列。

## 12. 培训与文档交付

交付物包括迁移报告、健康检查输出、客户端升级指引与一份《3.x 变更要点》一页纸。建议对客户 IT 团队做一次 60 分钟培训，重点是令牌有效期缩短带来的集成改造、旧上传接口的替换，以及不可回滚带来的运维纪律变化。
