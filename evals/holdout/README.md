# 前瞻冻结留出测试 v1

本轮在查看新题检索结果前冻结 `questions.json` 与 `protocol.json`（SHA-256 校验）。
题目来自已有合成语料的六篇文件，12 道有答案题、3 道资料缺失题、3 道跨库隔离题。
新题的问法和所需事实未用于此前重排序调参。隔离题有意复用本轮事实，但切换目标库；
不能把全部 18 题视为 18 个独立事实样本。原 168 题、标注及历史报告均保留。

这是助手构建的前瞻留出集，覆盖范围窄、并非独立人工盲测，也不是新语料泛化测试。
来源只列预先检查的明确证据；未穷举全语料的等价表达。严格证据命中失败不必然代表答案错误。
不在看完结果后补标签或调整策略；若今后修订，须创建新版并保留本轮结果。

## 固定方案

- `dense_3`：共同候选池中向量排序的前三条。
- `rerank_diverse_2`：同一前十条候选进行 BGE 重排，取三条，每文档软上限两条。
- 两组调用相同 Qwen 配置；按题交替生成先后顺序，不自动重试。
- 记录候选、分数、选中切片、引用、计时、错误和语料哈希。
- MySQL 核验命中文档所属库；隔离题同时检验真实拒答。
- 查询耗时来自共享 top-10 请求，不能称为独立 top-3 HTTP 服务延迟对照。
- 首次模型加载与预热不计入逐题重排耗时；窗口重排不属于这次生产选项对照。

## 运行

```bash
conda activate knowops
HF_HUB_OFFLINE=1 python scripts/evaluate_holdout.py
```

需要已运行的 API、MySQL、Milvus、索引完成的 synthetic-v1 三库，以及本地重排模型和 Qwen 配置。
本次每次完整运行最多产生 36 次 Qwen 调用；新运行保存为独立目录，不覆盖历史。
`results.json` 逐题增量保存，未完成时 summary 分母只包括已经尝试的题，不能当作最终结果。
程序启动失败会保留部分文件并以非零退出；必须核对完整 36 行后汇报。

## 如何解释

完整证据覆盖与引用证据覆盖均使用冻结来源/原文片段匹配，不能称为回答正确率。
`human_correct` / `human_supported` 保留 null，助手复核另存说明，不能冒充独立人工确认。
默认切换条件先于结果写入 protocol；小样本不能证明统计显著或真实生产收益。
